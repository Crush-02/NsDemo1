## 四、P0-1：建表改走 `data` 二维数组（核心）

### 4.1 设计取舍：改动收在 `initLuckysheet` 内部

`initLuckysheet` **保持对外签名 `(cells?: CellData[]) => void` 不变**，内部把扁平数组转成二维数组再传给 Luckysheet。

| 方案 | `importData` | `checkDraft` | 风险面 | 省下的对象构造 |
|---|---|---|---|---|
| A. 改签名（让调用方直接给二维数组） | 需改 | 需改 | 大 | 省 42.5 万对象（~115ms） |
| **B. 签名不变，内部转换（推荐）** | 不用改 | 不用改 | **小** | 仍构造 42.5 万对象（~115ms） |

**采用 B**：115ms 相对 5~7 秒的总时长可以忽略，换取「`importData`、`checkDraft`、未来任何调用方都不用动」。

### 4.2 新增工具函数（两个编辑器各一份，与现有平行副本结构一致）

```ts
/**
 * 把扁平的 celldata 转成 Luckysheet 的二维网格（下标=行号，元素=单元格对象或 null）
 *
 * 必须走 data 路径的原因：Luckysheet 的 buildGridData 在只给 celldata 时，
 * celldata 按行递增排列，每遇到一个新行号就调用 Zo() 复制整张已建好的表，
 * 整体是 O(行数²)。实测 44,579 行：只给 celldata > 180 秒（卡死），
 * 给 data 则 545ms。
 */
function toGridData(cells: CellData[], minRows: number, minCols: number): any[][] {
  let maxRow = 0
  let maxCol = 0
  for (const cell of cells) {
    if (cell.r > maxRow) maxRow = cell.r
    if (cell.c > maxCol) maxCol = cell.c
  }
  const rows = Math.max(maxRow + 1, minRows)
  const cols = Math.max(maxCol + 1, minCols)

  // 用 null 预填（不分配对象），保证表格有完整的可滚动区域
  const grid: any[][] = new Array(rows)
  for (let r = 0; r < rows; r++) grid[r] = new Array(cols).fill(null)
  for (const cell of cells) grid[cell.r][cell.c] = cell.v
  return grid
}
```

## 七、P0-3b：统计更新改「节流」

**文件**：`src/engine/finance/validationStore.ts`、`src/engine/validationStore.ts`（`updateStatsNow` 由调度器的 `updateStatsNow` 回调触发）

现状：每批都全量重算 —— `state.results.forEach(...)` 遍历已累积的全部结果（最终 19,233 条）+ `getFilledRowCount()` 全表扫描（44,575 行 × 18/32 列，单次 9ms）→ 累计 **8.0 秒**。

```diff

+ let lastStatsAt = 0
+ const STATS_THROTTLE_MS = 250
+

-   updateStatsNow()
+   const now = performance.now()
+   // 距上次不足 250ms 则跳过（校验结束时由 applyAllStylesFromResults 前的显式调用兜底）
+   if (now - lastStatsAt >= STATS_THROTTLE_MS) {
+     lastStatsAt = now
+     updateStatsNow()
+   }
  },
```

并在 `run()` 开始处重置 `lastStatsAt = 0`，在 `executeCrossRowPhase()`（全部校验完成）**无条件调用一次** `updateStatsNow()`，保证最终统计准确。

**为什么用节流而不是增量累加**：增量方案需在「用户中途编辑」「结果被 `clearCrossRowResultsForCol` 删除」「pendingCells 变化」等多条路径上同步维护计数器，语义容易漂移；节流改动最小、语义完全不变，且已能把 8.0 秒压到 < 0.1 秒（30 批 × 250ms 窗口 → 实际只算 3~5 次）。

## 一、问题回顾

导入后同一张表内日期出现两种形态：`2026-06-01` 与 `5/31/27` 混排。连带产生：

- 「格式_日期」HIGH 警告堆积（`计费结束日期` 整列触发）
- `validateBillingDateOrder`（计费结束日期必须晚于开始日期）被 `continue` 静默跳过 → 规则实际失效

---

## 二、根因链（已实测闭环，非推测）

| # | 发生的事 | 证据 |
|---|---|---|
| 1 | Excel 日期是数字序列号，但**每格的数字格式不统一** | 读 `cell.z`：I 列全 `yyyy/m/d;@`、J 列全 `m/d/yy`、K 列两种混用 |
| 2 | `readExcelFile` 用 `sheet_to_json({ raw:false })`，把每个日期按**它自己的格式**渲染成字符串 | 得到 `"2026/6/1"` 与 `"5/31/27"` 两种文本 |
| 3 | Luckysheet 写入单元格时自动识别日期（`xs()` → `ds()`），而 `ds()` 的判定正则**强制 4 位年份** | 从 UMD 包抠出 `ds()` 实跑：`ds("2026/6/1")=true`、`ds("5/31/27")=false` |
| 4 | 命中的转日期型显示 `YYYY-MM-DD`，不命中的保持文本 → **同列两种形态** | 端到端复刻与用户截图 6/6 行逐格一致 |

**关键更正**：上一轮"全项目没有任何一处对日期做转换"只对一半——业务代码确实不转换，**转换真实发生在 Luckysheet 内部**，这也是"为什么有的列全过、有的列全不过"的真正解释。

## 三、修复目标与验收标准

| 目标 | 验收标准 |
|---|---|
| Excel 认定为日期的单元格，导入后统一 `YYYY-MM-DD` | 用户文件 **18/18** 个日期单元格输出 `YYYY-MM-DD` |
| 非日期单元格零影响 | 逐格比对：变化数 **=== 18**，其余 0 差异 |
| 导入后 Luckysheet 全部识别为日期型 | 18/18 命中 `ds()` → 显示统一、`ct.t='d'` |
| 校验联动修复 | 合法数据上「格式_日期」警告归零；`validateBillingDateOrder` 不再被跳过 |

## 四、方案选型

| 方案 | 做法 | 评价 |
|---|---|---|
| A. 列白名单 | 只对已知日期列做文本解析 | ✗ **Excel 列索引 ≠ 工具列索引**（房产模块自 col19 起偏移 2），只能在 remap 后做，且要维护两套列清单 |
| B. Date 对象 | 保留 `cellDates:true`，用 `dayjs(cell.v)` 走现成的 `val instanceof Date` 分支 | ✗ **实测差一天**：xlsx 给的 Date 是本地 `2026-05-31 23:59:17`，格式化得 `2026-05-31`，期望 `2026-06-01` |
| **C. 格式驱动（推荐）** | 按单元格数字格式判定：`cell.t==='n' && SSF.is_date(cell.z)` → `SSF.format('yyyy-mm-dd', cell.v)` | ✓ 用 Excel 自己的序列号体系，**零时区风险**；**零列清单**；excelIO 层一次改动、双模块自动生效 |

选 C 的三个硬理由：
1. **Excel 自己认定它是日期**——判定依据来自文件本身，不是我们的猜测，零误伤（文本单元格 `z` 是 `General`/`@`，天然不满足）
2. **绕开 `cellDates` 的差一天缺陷**（方案 B 的致命伤）
3. **不需要知道哪些列是日期列**，规避了"工具列序 ≠ Excel 列序"这个陷阱

## 五、推荐方案详细设计

### 5.1 改动面

**唯一改动文件**：`src/utils/excelIO.ts` → `readExcelFile()`

- 函数签名**不变**：`(file, maxCols?, headerRowIndex?) => Promise<{headers, rows}>`
- 返回类型**不变**：仍是 `string[][]`
- 因此 `Toolbar.vue`、`App.vue`、`TableEditor.vue`、`FinanceTableEditor.vue` 的 `importData`、`remapRows`、校验引擎、导出逻辑**全部无需改动**

### 5.2 三处改动 + 一处删除

| # | 位置 | 改动 |
|---|---|---|
| 1 | `XLSX.read` 参数（第 67 行） | `{ type:'array', cellDates:true }` → `{ type:'array', cellNF:true }`<br>去掉 `cellDates` 拿回数字序列号；加上 `cellNF` 拿回 `cell.z`（不传时 `z` 为 `undefined`） |
| 2 | 新增 `buildDateMap(sheet)` | 遍历 `!ref` 范围，收集「数字格式为日期」的单元格，产出 `"{行下标}_{列下标}" -> 'YYYY-MM-DD'` |
| 3 | `normalized`（第 96-109 行） | 每个单元格**优先取日期映射**，未命中才走原有字符串逻辑 |
| 4 | 删除 `val instanceof Date → dayjs(...)` 分支 | 该分支永不触发，且**一旦触发会差一天**，是定时炸弹 |

**实测等价性**：改动 1 的两种参数下，`sheet_to_json(raw:false)` 输出**逐格 0 差异**（6 行 × 21 列全比对），所以 `rows` 行为完全不变。

### 5.3 核心算法（伪代码）

```ts
const MAX_SERIAL = 2958465                       // 9999-12-31
const DATE_RE = /^\d{4}-\d{2}-\d{2}$/

function buildDateMap(sheet: XLSX.WorkSheet): Map<string, string> {
  const map = new Map<string, string>()
  if (!sheet || !sheet['!ref']) return map
  const range = XLSX.utils.decode_range(sheet['!ref'])
  for (let R = range.s.r; R <= range.e.r; R++) {
    for (let C = range.s.c; C <= range.e.c; C++) {
      const cell = sheet[XLSX.utils.encode_cell({ r: R, c: C })]
      if (!cell || cell.t !== 'n' || !cell.z || !XLSX.SSF.is_date(cell.z)) continue
      const serial = cell.v
      if (typeof serial !== 'number' || !isFinite(serial)) continue
      if (serial < 1 || serial > MAX_SERIAL) continue            // 挡 0 与越界
      const out = XLSX.SSF.format('yyyy-mm-dd', serial)
      if (!DATE_RE.test(out)) continue                           // 挡 1900-01-00 / 空串
      map.set(`${R - range.s.r}_${C - range.s.c}`, out)
    }
  }
  return map
}
```

`normalized` 阶段的接入点：

```ts
const normalized = dataRows.map((row: any[], i: number) => {
  const arr: string[] = []
  const rowIdx = headerRowIndex + 1 + i          // 还原为 rows 数组下标
  for (let c = 0; c < maxCol; c++) {
    const dv = dateMap.get(`${rowIdx}_${c}`)     // 日期优先
    if (dv !== undefined) { arr.push(dv); continue }
    const val = row[c]
    if (val === null || val === undefined) arr.push('')
    else arr.push(String(val).trim())
  }
  return arr
})
```

### 5.4 两个关键实现约束

1. **行下标必须用 `R - range.s.r`**：`sheet_to_json` 的输出数组下标是**相对 `!ref` 起点**的（已实测：合成表 `!ref=A3:B4` 时输出下标 0 对应 sheet 第 3 行），不能直接用绝对行号。
2. **`XLSX.SSF` 类型安全**：`node_modules/xlsx/types/index.d.ts` 里声明为 `export const SSF: any`，所以 `XLSX.SSF.is_date` / `XLSX.SSF.format` 可直接调用，**不需要类型断言**。

## 七、明确不做的事（边界）

1. **不 patch Luckysheet UMD** — `ds()` 是三方库行为，改包体维护成本高、升级即失效。
2. **不解析"文本型日期"** — 即 `t:'s'` 的 `"5/31/27"`。这类值 Excel 本身没认定是日期，强行猜测会引入 `m/d/yy` vs `d/m/yy` 的歧义。列为 P2-b 可选。
3. **不改校验规则本身** — `isValidDateStr` 已接受 `YYYY-MM-DD`，归一后自然通过。
4. **不改 `importData` / `remapRows` / 校验引擎 / 导出** — 无必要。

## 十、Excel 未认定为日期格式时会怎样（实测降级矩阵）

造了 12 个样本单元格（覆盖常规格式/文本格式/数字格式/英式日期/中文日期/非法序列号/空值）跑完整链路，结果分**两档**：

### 档位一：Luckysheet 会兜住（新方案无需处理，本来就没问题）

| 情形 | Excel 存法 | 新逻辑输出 | 最终显示 | 校验 |
|---|---|---|---|---|
| 文本格式 + `2024/6/1` | `z='@'` `t='s'` | `2024/6/1`（不归一） | **2024-06-01** | ✓ 通过 |

原因：Luckysheet 的 `ds()` 只要求「4 位年」，文本型日期只要带 4 位年就会被自动转成日期型。**所以文本日期里"看起来正常"的那些，本来就没事。**

### 档位二：新方案覆盖不到，但**不会静默出错，而是明确报「格式_日期」HIGH 警告**

| 情形 | Excel 存法 | 最终显示 | 校验 |
|---|---|---|---|
| **B. 常规格式 + 裸序列号** | `z='General'` `v=46174` | `46174` | ✗ 警告 |
| **D. 文本格式 + 2 位年** | `z='@'` `v='5/31/27'` | `5/31/27` | ✗ 警告 |
| **E. 日期格式 + 文本值** | `z='m/d/yy'` `v='5/31/27'` | `5/31/27` | ✗ 警告 |
| **L. 数字格式 + 序列号** | `z='0.00_ '` `v=46174` | `46174.00` | ✗ 警告 |
| **F. 非法序列号 0** | `z='m/d/yy'` `v=0` | `1/0/00` | ✗ 警告（合理，0 不是日期） |

**这是"安全失败"而非"静默出错"**：财务会看到红色警告去核对，而不是带着错日期一路导入系统。空单元格不受影响（`validateDateField` 对空值直接 `return null`，且 `importData` 不会把空值写进表格）。

### 顺带发现：C 方案对"奇怪的日期显示格式"天然免疫（这是它相对旧逻辑的最大增值）

| 情形 | Excel 显示 | 旧逻辑（文本直读） | 新逻辑 |
|---|---|---|---|
| `dd/mm/yyyy`（英式） | `01/06/2026` | 原样 `01/06/2026`，报格式错误 | **2026-06-01** ✓ |
| `yyyy年m月d日` | `2026年6月1日` | 原样 `2026年6月1日`，报格式错误 | **2026-06-01** ✓ |

因为新逻辑用的是**序列号**（无歧义），而不是解析显示文本 —— 这反过来证明"解析文本"是最差的技术路线。

### 幽灵日期 60（1900-02-29）

`serial=60` 会归一为 `1900-02-29`，但 Luckysheet 的 `ds()` 内部有闰年校验（`new Date(1900,1,29).getDate() !== 29`）会拒绝它 → 保持文本 → 报格式错误。**行为正确**，无需特殊处理。

### 11.2 建议实施：文本日期归一（把 P2-b 收窄成安全子集）

在 `excelIO.ts` 新增 **1 个导出函数**，`TableEditor.vue` / `FinanceTableEditor.vue` 在 **remap 之后**各调用 1 次（工具侧列索引才有效）：

```ts
normalizeDateColumns(rows: string[][], dateCols: number[]): string[][]
```

**判定规则（三条同时满足才转换）**：
1. 仅限**日期列**（`FINANCE_DATE_COLUMNS` / `DATE_COLUMNS`）—— 杜绝误伤备注、合同编号等列
2. 仅认 **4 位年开头**：`^\d{4}[.\-/]\d{1,2}[.\-/]\d{1,2}$`、`^\d{4}年\d{1,2}月\d{1,2}日$`
3. 必须是**真实存在的日期**（月 1–12、日符合当月天数、闰年）→ 输出 `YYYY-MM-DD`

**明确不认**：2 位年（`25/7.31`）、脏数据（`2025//11/4`、一格两个日期）—— 继续报「日期格式错误」让人工核对，**绝不猜**。

**预期收益**：消除其中 **324 格**误报（占全部漏网值的 93%），且新增仅 3 处小改动。

# 2026-10-08 工作日志

## 追问核查：改走 `data` 后 Luckysheet 不再维护 `sheet.celldata` 的影响（仅分析，未编码）

背景：承接 09-30 的《大数据量导入性能优化方案》P0-1（建表改传 `data` 二维数组）。用户要求详细说明其影响。

### 核心纠正：**Luckysheet 从来不"维护" `celldata`**

真实 Chromium 实测（**现状路线 A，只传 celldata**）：

| 步骤 | `flowdata` | `sheet.celldata` |
|---|---|---|
| `create` 后 | 304 行 | 1501 条 |
| `setCellValue(5,1,"EDITED")` 后 | (5,1)=`"EDITED"` ✅ | (5,1) 仍=`"v1_1"` ❌ 未更新 |

⇒ `celldata` 从 `create` 起就是**只读快照**。现行「flowdata + celldata 双写」并**不是在配合 Luckysheet**，而是在维护一份 Luckysheet 自己都不读的副本。
准确表述：路线 C 下 **`sheet.celldata` 这个键根本不出现**（实测 `hasOwnProperty('celldata') === false`）。

### 逐处影响（全部实测）

| 位置 | 路线 C 行为 | 处置 |
|---|---|---|
| `initLuckysheet(extraCelldata?)` | 改动本体 | **必须改** |
| `importData`（两个编辑器） | 改直接产出二维数组，省 42.5 万对象 | **必须改** |
| `checkDraft` 草稿恢复 | `draft.celldata.filter` → `initLuckysheet(dataCells)`，不改会**又走回 O(n²)** | **必须改（最易漏）** |
| `autoSave.getCurrentCelldata()` | 从 `getSheetData()` 反推，不读 `sheet.celldata` | ✅ 无影响 |
| `handleBulkEdit` celldata 双写 | `sheet?.celldata \|\| []` 得**临时空数组**，push 内容直接丢弃（实测无异常） | ✅ 无影响；建议删除 |
| `handleBulkDelete` celldata 清理 | `Array.isArray(undefined)` = false → 整段跳过 | ✅ 安全；建议连 `cellsToDelete` 构建一起跳过（否则白建 72 万字符串） |
| 房产 `engine/validationStore.ts` 的 `celldata.findIndex` | celldata 空 → 循环不执行，**O(n²) 自然消失** | ✅ P2 项可取消 |
| 导出 `exportExcel` | 读 flowdata + `getAllSheets()[0].config.merge`（实测保留） | ✅ 无影响 |
| Luckysheet 内部 | 真正读 `sheet.celldata` 的只有**多表懒加载**（`loadSheetUrl`，本项目未启用）；其余是 `iscelldata()` 与透视表自身的 `celldata`（同名不同物） | ✅ 无影响 |

### 其他兼容项实测（路线 C）
表头样式 `{bg,fc,ht,bl}` 完整保留 ✓；`config.merge` 保留 ✓；编辑/滚动正常 ✓；
28,000 行：build 126ms + create **608ms**（139MB）✓；
Luckysheet 另有 `transToCellData` API（flowdata→celldata 一次性转换），未来若确需 celldata 可用它重建。

### 落地建议
`initLuckysheet(cells: CellData[])` **保持对外签名不变**，内部一次转成二维数组 → `importData`/`checkDraft`/未来调用方都不用改，风险面最小（代价仍构造 42.5 万对象，约 115ms）。

## 编码方案定稿（仅出方案，未编码）

### 6 项改动、约 7 个文件、~200 行
| 编号 | 项 | 文件 | 关键设计 |
|---|---|---|---|
| P0-2 | 只解析第一个工作表 | `utils/excelIO.ts` | `XLSX.read(..., { sheets: 0 })`（一行） |
| P1-1 | `buildDateMap` 只遍历实际单元格 | `utils/excelIO.ts` | 改用 `Object.keys(sheet)` + `decode_cell`，跳过 `!` 前缀键 |
| P0-1 | 建表改走 `data` 二维数组 | 两个 `*TableEditor.vue` | 新增 `toGridData(cells, minRows, minCols)`；**`initLuckysheet` 对外签名不变**，内部转换 → `importData`/`checkDraft` 都不用改 |
| P0-3a | 调度器时间预算分批 | `engine/validationScheduler.ts` | 新增 `frameBudgetMs=25`，`executeBatch` 内 `while` 跑满预算，892 批 → ~30 批 |
| P0-3b | 统计更新节流 | 两个 `validationStore.ts` | `250ms` 节流 + 校验结束无条件兜底一次（**用节流而非增量**：避免在多条结果变更路径上维护计数器导致语义漂移） |
| P1-2 | 清理 celldata 死逻辑 | 两个 `validationStore.ts` | `handleBulkDelete` 的 `cellsToDelete`（72 万字符串）加前置守卫；`handleBulkEdit` 双写段跳过 |

### 关键取舍
- `initLuckysheet` **签名不变**、内部转二维：牺牲 115ms 的对象构造，换取 `importData`/`checkDraft`/未来调用方零改动 → 风险面最小
- `row` 参数统一设为 `gridData.length`（同时决定滚动条与网格范围，最稳）
- 房产模块 `row/column` 写在 **sheet 层**，应收模块写在 **config 内**，改时勿混淆

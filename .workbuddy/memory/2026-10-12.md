## 【分析】校验面板 19,233 条警告卡死 — 方案已出，未编码

方案文档：`.workbuddy/docs/校验面板大数据量卡死-优化方案.md`（即检阅报告中的 P1-8）

### ⚠️ 关键结论：不是 JS 计算慢，是 DOM 爆炸
实测 19,283 条：`getAllCellErrors` 10.1ms + `filter` 9.0ms + `groupByRow` 10.1ms ≈ **30ms**，一帧量级，**不可能是根因**。
若按「数据量大→JS 慢」去优化（增量统计/缓存分组）方向就错了。

**真根因**：展开瞬间一次性创建
- DOM 节点 **≈136,768**（10,685 行分组 + 19,233 条目 + 每条 4 个 span）
- 内联 `@click` 监听器 **19,233 个**
- 一次性布局 13.7 万盒模型

**4 个放大因素**：
1. `.error-msg { word-break: break-all }`（`FinanceValidationPanel.vue:503`）— 逐字符断行，30 字中文在 360px 面板换行 3~4 行，布局耗时**数倍**放大。**单行改动、零风险、收益最大**
2. `getAllCellErrors()` 被 `errorGroups`+`warningGroups` 重复调 2 次（+`counts` 3 次 = 5 次全量遍历）
3. `:key` 读 `messages[0]` 拼字符串 → 19,233 次，且同格多条同消息时**key 重复**
4. `slide` 过渡 + `drawer-expand` 动画与巨量创建同帧

**重要前提**：三抽屉改造（`1e7a450`）已让「默认收起」生效 → **打开面板是快的，卡死发生在用户点「警告」展开的瞬间**。

### 推荐顺序
| 阶段 | 项 | 成本 | 收益 |
|---|---|---|---|
| 一（1~2h） | E1 去 break-all + E3 简化 key + F3「仅显示错误」开关 | 1+1+15 行 | 立即不卡 |
| 二（0.5~1d） | **D 按消息聚合去重** + E2 单次遍历 | ~50 行×2 | 19233→几十，**数量级** |
| 三（可选） | A2/B 虚拟滚动 | ~80 行×2 | 天花板最高 |

> **D 聚合性价比最高**：截图中 19,233 条几乎全是同一条「支付方式必须为…」，聚合成 `⚠ 共 12,846 处 · 列 H` 只需几十个节点，且比逐条更好用。
> **F3 直击用户意图**：截图右下显示「错误 0」，用户点开面板想看的是错误，而这 19,233 条全是警告 —— 很可能根本不是他要的。

## 【设计】方案 D 聚合去重 设计详解（未编码）

文档：`.workbuddy/docs/方案D-按消息聚合去重-设计详解.md`

### 实测收敛比（按真实消息构造 44,562 行典型错误分布）
**20,329 条 → 37 组**；DOM **≈122,048 节点 → ≈272（449×）**；监听器 20,329 → 37
收敛来源：19,996 条「支付方式必须为…」整列未填；200 条金额格式；50+50 必填/枚举

### ⚠️ 关键设计陷阱：不能只按 message 聚合
扫 `engine/finance/` 全部消息后发现**有些文案不含列名**：
`"缴款金额、缴款日期、支付方式三个字段需同时填写或同时为空"`
→ 实际出现在 **col 13 / 15 / 16 三个列**；只按 message 聚合会混组，用户不知是哪列。
**正确键：`${col}||${message}`（二元组）**

也不能用 `results` 的 Map key（`"row-col"`）—— 那是行级的，2 万行会得到 2 万个 key，起不到聚合作用。

### 设计要点
- 类型 `AggregatedIssue { key, col, colLabel, message, severity, count, rows }`
- **保留 rows 数组**：二级展开明细 + 定位；19,996 个数字 ≈160KB 可接受
- 聚合视图按 `count` 降序（数量多的先显示）
- 二级展开**必须再限量 100 条**，否则 19,996 条照样打死浏览器（问题只是推迟一层）
- 放 **store 层**（两面板共用，避免第三次复制），保持"面板只读 store"的分层约定
- 顺带做 E2：`errorGroups`/`warningGroups` 共用一次遍历

### 6 个边界（已识别）
1. **动态文案不收敛** —「房产简称"X"的收费科目"Y"在计费周期(a~b)内重复」每条都不同；长期建议给 `ValidationResult` 加 `ruleId`+`params`（改 30+ 处，放阶段三）
2. 组数为 0 → 沿用现有判断
3. count=1 → 不显示展开按钮，点击直接定位
4. rows 过大（>10万）→ 评估只存 count+首批
5. **`Map` 插入序不保证行号有序** → 必须显式 `.sort((a,b)=>a-b)`，否则行号展示乱序
